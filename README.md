From Raw Data to Business Intelligence

📌 1. Project Overview

AdventureWorks Data Analytics is a large-scale, end-to-end Data Warehouse and Business Analytics project designed to transform raw transactional data into a structured, reliable, and business-ready analytical environment.

The project covers the complete data lifecycle, starting with raw data ingestion, followed by data cleaning, transformation, integration, and dimensional modeling.

It implements a multi-layered Data Warehouse architecture using the Medallion Architecture (Bronze, Silver, and Gold), with a Star Schema serving as the foundation for downstream analytical processes.

On top of the Data Warehouse, a comprehensive SQL-based and Python Business Analytics framework investigates business performance across three major domains:

- 📈 Sales Analytics
- 👥 Customer Analytics
- 📦 Product Analytics

The project consists of multiple interconnected SQL scripts, database objects, stored procedures, transformation processes, and analytical reports using Python and SQL. Each component serves a specific purpose within the overall architecture and depends on the successful completion of preceding stages.

This is not a collection of isolated SQL queries. It is a comprehensive, multi-stage Data Engineering and Business Analytics solution designed to transform raw data into actionable business insights.

---

⚠️ 2. Project Execution Order & Dependencies

IMPORTANT: The Data Warehouse must be fully implemented and populated before executing any Business Analytics scripts.

The project is organized into two main components:

1. "01_Warehouse_Part"
2. "02_SQL_Analysis_Part"
3. "03_Python_Analysis_Part"

The analytical reports depend on the Gold layer tables and database objects generated by the Data Warehouse implementation.

Executing analytical scripts before completing the warehouse setup will result in missing-object errors or incomplete analytical results.

🔄 Required Execution Sequence

The correct implementation and execution order is:

Step| Component| Description
01| 🏗️ Data Warehouse Setup| Initialize the database, schemas, tables, and required objects
02| 🥉 Bronze Layer| Create raw staging tables and execute data ingestion procedures
03| 🥈 Silver Layer| Execute data cleaning, standardization, and transformation processes
04| 🥇 Gold Layer| Build and populate fact and dimension tables using Star Schema
05| 📊 Business Analytics| Execute Sales, Customer, and Product analytical scripts

📋 Execution Guidelines

Before Starting:

- Ensure Microsoft SQL Server is installed and running.
- Prepare the original source CSV files.
- Configure the required database and file paths.
- Review the scripts and their execution dependencies.

During Data Warehouse Implementation:

- Execute the initialization scripts first.
- Create the Bronze, Silver, and Gold schemas and their required objects.
- Execute the loading procedures in the correct order.
- Verify successful data ingestion and transformation between layers.
- Confirm that the Gold fact and dimension tables are properly populated.

«⚠️ Important: Do not skip warehouse stages or execute analytical reports before the Gold layer is ready. The Business Analytics component is designed to consume the final business-ready warehouse data.»

🏗️ Part 01: Data Warehouse Engineering

The Data Warehouse component establishes the technical foundation of the project.

It follows the Medallion Architecture, organizing data into three progressively refined layers.

🥉 3. Bronze Layer - Raw Data Ingestion

🎯 Purpose

The Bronze layer serves as the initial landing zone for raw source data, preserving the original data structure before applying cleaning or transformation logic.

🔧 Key Implementation Areas

- Ingesting source CSV files into SQL Server.
- Creating staging tables for raw datasets.
- Using "BULK INSERT" for data loading.
- Applying "TABLOCK" for bulk loading.
- Implementing dynamic SQL using "sp_executesql".
- Developing centralized loading procedures.
- Preserving raw data for downstream processing.

📂 Main Components

- Bronze staging tables.
- "bronze.load_bronze" stored procedure.
- Centralized raw data ingestion process.

💡 Business & Technical Value

Establishes a consistent data ingestion mechanism while maintaining the original source data for subsequent processing.

---

🥈 4. Silver Layer - Data Cleaning & Transformation

🎯 Purpose

Transform raw data into clean, standardized, and consistent datasets suitable for analytical modeling.

🧹 Key Data Cleaning & Transformation Operations

- Removing duplicate records.
- Standardizing inconsistent values.
- Handling missing and inconsistent data.
- Applying appropriate data type conversions.
- Validating data consistency across entities.
- Implementing business rules and transformation logic.
- Applying date-related transformations.
- Using SQL analytical and window functions where required.

📂 Main Components

- Cleaned Silver tables.
- "silver.load_silver" stored procedure.
- Structured transformation processes.

💡 Business & Technical Value

Improves data quality, reliability, and consistency before loading the final analytical model.

---

🥇 5. Gold Layer - Business-Ready Data Modeling

🎯 Purpose

Build the final analytical layer containing structured fact and dimension tables designed for reporting and business intelligence.

⭐ Data Modeling - Star Schema

The project follows dimensional modeling principles by separating measurable business events from descriptive business attributes.

📌 Dimension Tables

Dimension Table| Description
"gold.dim_customers"| Customer demographic and descriptive attributes
"gold.dim_products"| Product descriptive and classification attributes

📊 Fact Table

Fact Table| Description
"gold.fact_sales"| Transaction-level sales measures and foreign keys

🔗 Data Modeling Principles

- Defining the fact table grain at the item/order-line level.
- Establishing primary keys for dimension tables.
- Implementing foreign key relationships.
- Applying one-to-many relationships from dimensions to facts.
- Maintaining referential consistency.
- Separating descriptive attributes from transactional measures.

💡 Business & Technical Value

Creates a centralized and reusable analytical foundation for consistent business reporting and multidimensional analysis.
